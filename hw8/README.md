# HW9

## Подготовка проекта

### Локальная база данных

База данных разворачивается **локально** на вашем компьютере через Docker.

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/)
   (Windows: при установке включите WSL 2; macOS: подходит и Intel, и Apple Silicon).
2. В корне проекта выполните:

   ```bash
   docker compose up -d
   ```

   Поднимутся два контейнера:
   - **MariaDB** на `localhost:3306`, база `wp`, пользователь `wp`, пароль `wp`;
   - **Adminer** — веб-интерфейс к БД на <http://localhost:8081>
     (System: `MySQL / MariaDB`, Server: `db`, Username: `wp`, Password: `wp`, Database: `wp`).
3. Параметры подключения уже прописаны в `profile.properties` — менять их не нужно.

Полезные команды:

| Что сделать | Команда |
|---|---|
| Запустить БД | `docker compose up -d` |
| Остановить БД (данные сохранятся) | `docker compose stop` |
| Консоль MariaDB | `docker compose exec db mariadb -uwp -pwp wp` |
| Логи БД | `docker compose logs db` |

**Данные сохраняются** между запусками: после `docker compose stop` / `up -d`, закрытия Docker Desktop,
перезагрузки ноутбука и `docker compose down` всё на месте — база хранится в томе Docker `db-data`.
Задание сдаётся на вашем ноутбуке с вашими данными, поэтому **не удаляйте том `db-data`**
(например, в Docker Desktop → Volumes).

Таблицы создаёт сам Hibernate при запуске приложения (`spring.jpa.hibernate.ddl-auto=update`).
Ручные изменения (колонки, записи) выполняйте через Adminer (<http://localhost:8081> → «SQL-запрос») или консоль.

### Запуск приложения

Нужна JDK 17 (подойдёт любая от 8 до 17; отдельно ставить Maven не обязательно — в проекте есть Maven Wrapper):

```bash
./mvnw spring-boot:run        # macOS / Linux
mvnw.cmd spring-boot:run      # Windows
```

Или запустите класс `ru.itmo.wp.WpApplication` из IntelliJ IDEA. Сайт откроется на <http://localhost:8080>.

### Если что-то не работает

- **Ошибка подключения к БД при запуске** — БД не запущена. Проверьте `docker compose ps`.
- **Порт 3306 занят** (у вас уже стоит MySQL/MariaDB) — в `docker-compose.yml` замените `"3306:3306"`
  на `"3307:3306"` и в `profile.properties` укажите порт `3307`.
- **Изменили `profile.properties`, а подключение не поменялось** — параметры подставляются при сборке,
  выполните `./mvnw clean` и запустите заново.
- **`./mvnw: Permission denied`** — выполните `chmod +x mvnw`.

### Первый запуск

1. Запустите БД и приложение (см. выше)
2. Запуск создаст таблицы:
   - `user`
   - Другие необходимые таблицы
3. Добавьте к таблице `user` колонку `passwordSha` со значением по умолчанию `NULL`, например через Adminer:

   ```sql
   ALTER TABLE `user` ADD COLUMN `passwordSha` VARCHAR(255) DEFAULT NULL;
   ```
4. Убедитесь, что всё работает:
   - Регистрация
   - Вход
   - Выход
   - Просмотр пользователей
5. Создайте нескольких пользователей
6. Назначьте права вручную (добавьте записи в `user_role`), например:

   ```sql
   INSERT INTO `user_role` (`user_id`, `role_id`)
   SELECT u.id, r.id FROM `user` u, `role` r WHERE u.login = 'ваш_логин' AND r.name = 'ADMIN';
   ```

## Задача 1: Сущность Comment и функциональность комментариев

##### Добавление сущности Comment
- Создайте сущность `Comment` с полями:
  - `id`
  - `text` (используйте аннотацию `@Lob`)
  - `user`
  - `post`
  - `creation_time`

##### Настройка связей
- Добавьте `List<Comment> comments` в сущность `Post`
- Настройте двунаправленный мэппинг:
  - `Many-to-one` и `one-to-many` для отношения комментарий-пост
- Настройте однонаправленный мэппинг:
  - `Many-to-one` для отношения комментарий-пользователь
  - Комментарий знает своего пользователя, но у пользователя не хранятся комментарии

##### Функциональность
- Создайте страницу для отображения поста и комментариев по URL `/post/{id}`
- Отображайте комментарии в хронологическом порядке
- Для авторизованных пользователей добавьте форму добавления комментария (`textarea` для текста и кнопка отправки)
- Измените главную страницу: заголовки постов по клику должны вести на страницу индивидуального поста

## Задача 2: Сущность Tag и отношение многие-ко-многим

##### Добавление сущности Tag
- Создайте сущность `Tag` с полями:
  - `id`
  - `name`

##### Настройка связи с Post
- Реализуйте отношение многие-ко-многим между `Tag` и `Post`
- Сделайте однонаправленный мэппинг:
  - Добавьте поле `Post#tags`
  - Реализуйте связи по образцу связей пользователей и ролей

##### Инициализация данных
- Добавьте несколько тегов вручную (записи в таблицу `tag`)
- Добавьте связи между постами и тегами (записи в таблицу `post_tag`)
- Отображайте список тегов при показе поста

## Задача 3: Добавление тегов в форму создания поста

##### Расширение формы
- Добавьте поле `Tags` в форму создания поста
- Реализуйте ввод тегов через пробельные символы (whitespaces)

##### Валидация
- Выполняйте проверку тегов после разбиения на слова:
  - Теги должны состоять только из латинских букв
  - Выбрасывайте ошибку валидации для некорректных тегов

##### Сохранение
- При сохранении нового поста:
  - Сохраняйте пост вместе с тегами
  - Добавляйте новые теги в таблицу `tag` при необходимости
  - Используйте существующие теги, где возможно (тэги должны быть уникальны)
