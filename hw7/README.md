# Техническое задание

## Подготовка проекта

### Локальная база данных

База данных разворачивается **локально** на вашем компьютере через Docker.

1. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/)
   (Windows: при установке включите WSL 2; macOS: подходит и Intel, и Apple Silicon).
2. В корне проекта выполните:

   ```bash
   docker compose up -d
   ```

   Поднимутся два контейнера:
   - **MariaDB** на `localhost:3306`, база `wp`, пользователь `wp`, пароль `wp`;
   - **Adminer** — веб-интерфейс к БД на <http://localhost:8081>
     (System: `MySQL / MariaDB`, Server: `db`, Username: `wp`, Password: `wp`, Database: `wp`).
3. Параметры подключения уже прописаны в `profile.properties` — менять их не нужно.

Полезные команды:

| Что сделать | Команда |
|---|---|
| Запустить БД | `docker compose up -d` |
| Остановить БД (данные сохранятся) | `docker compose stop` |
| Консоль MariaDB | `docker compose exec db mariadb -uwp -pwp wp` |
| Логи БД | `docker compose logs db` |

**Данные сохраняются** между запусками: после `docker compose stop` / `up -d`, закрытия Docker Desktop,
перезагрузки ноутбука и `docker compose down` всё на месте — база хранится в томе Docker `db-data`.
Задание сдаётся на вашем ноутбуке с вашими данными, поэтому **не удаляйте том `db-data`**
(например, в Docker Desktop → Volumes).

Таблицы создаёт сам Hibernate при запуске приложения (`spring.jpa.hibernate.ddl-auto=update`).
Ручные изменения (колонки, записи) выполняйте через Adminer (<http://localhost:8081> → «SQL-запрос») или консоль.

### Запуск приложения

Нужна JDK 17 (подойдёт любая от 8 до 17; отдельно ставить Maven не обязательно — в проекте есть Maven Wrapper):

```bash
./mvnw spring-boot:run        # macOS / Linux
mvnw.cmd spring-boot:run      # Windows
```

Или запустите класс `ru.itmo.wp.Hw8Application` из IntelliJ IDEA. Сайт откроется на <http://localhost:8080>.

### Если что-то не работает

- **Ошибка подключения к БД при запуске** — БД не запущена. Проверьте `docker compose ps`.
- **Порт 3306 занят** (у вас уже стоит MySQL/MariaDB) — в `docker-compose.yml` замените `"3306:3306"`
  на `"3307:3306"` и в `profile.properties` укажите порт `3307`.
- **Изменили `profile.properties`, а подключение не поменялось** — параметры подставляются при сборке,
  выполните `./mvnw clean` и запустите заново.
- **`./mvnw: Permission denied`** — выполните `chmod +x mvnw`.

### Первый запуск

1. Запустите БД и приложение (см. выше)
2. Запуск создаст таблицу `user`
3. Добавьте к таблице колонку `passwordSha` со значением по умолчанию `NULL`, например через Adminer:

   ```sql
   ALTER TABLE `user` ADD COLUMN `passwordSha` VARCHAR(255) DEFAULT NULL;
   ```
4. Убедитесь, что всё работает:
   - Регистрация
   - Вход
   - Выход
   - Просмотр пользователей

## Задача 1: Страница профиля пользователя

- Создайте страницу профиля пользователя по ссылке `/user/{id}`
- Используйте параметр в методе контроллера с аннотацией `@PathVariable`
- Отобразите данные пользователя (`id`, `login`, `creationTime`) или надпись "No such user" если пользователь не существует
- Исправьте отображение логотипа и иконок языков на странице со списком пользователей

## Задача 2: Сущность Notice

- Добавьте сущность `Notice` с полями:
  - `id`
  - `content` (используйте аннотацию `@Lob`)
  - `creationTime`
- Заметка: `Notice` не имеет связи с `User` (пока без связей)
- Создайте:
  - `NoticeRepository`
  - `NoticeService`
- В классе `Page` добавьте метод `getNotices` (аналогично `getUser`) с аннотацией `@ModelAttribute`
- Все потомки `Page` должны добавлять в модель переменную `notices`
- Измените `commons.ftlh`:
  - Замените блок "Pay Attention" на серию блоков, отображающих все notices
- Добавьте несколько notices через базу данных
- Убедитесь, что на всех страницах отображаются notices в сайдбаре

## Задача 3: Форма добавления Notice

- Добавьте форму для создания `Notice`
- Форма должна содержать:
  - Одну `<textarea>` для содержимого
  - Кнопку "Add"
- Реализуйте валидацию вводимых данных

## Задача 4: Блокировка пользователей

- Добавьте пользователям колонку/поле `disabled` (по умолчанию `false`)
- На странице `/users` добавьте колонку с действиями
- В каждой строке таблицы разместите одну кнопку (доступ только для админов):
  - `Disable` для активных пользователей
  - `Enable` для заблокированных пользователей
- Реализуйте функциональность:
  - При нажатии кнопки отправляется форма, устанавливающая новый статус пользователя
  - Семантика обработки: "установить заданный статус", а не "сменить статус на противоположный"
  - После обработки формы страница перегружается с обновленными статусами
- Добавьте проверку на странице входа: при попытке входа заблокированного пользователя сообщение "User is disabled"

## Бонус 1
